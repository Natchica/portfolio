## Quick Reference

### Development

```bash
# Start both backend and frontend
make dev

# Or individually:
make dev-backend    # Axum at localhost:3000
make dev-frontend   # Trunk at localhost:8080 (proxies /api/ to backend)

# A second preview, for example from a git worktree:
cd frontend && trunk serve --port 8081
```

`make dev` runs `make check-port` first and refuses to start while port 3000 is taken: it prints the listener from `ss -ltnp` and stops. The check is skipped when `ss` is not installed.

Query parameters on any page:

| Parameter | Effect |
| --------- | ------ |
| `?webgl=off` | Forces the DOM look, for comparison and debugging. No notice is shown |
| `?webgl=failed` | Same DOM look with the notice. `scene.js` sets it itself when Three.js or the context fails |
| `?debug` | Exposes `window.__webgl` (state and measurement helpers) and enables `?force=touch,reduce` |

### Testing and validation

```bash
make test

# Rust gate, the single completion signal (never bare `cval`):
cval portfolio-frontend
cval portfolio-backend
```

Native unit tests cover the render-mode decision (`utils/render.rs`), the glyph grid encoder (`components/poneglyph_overlay.rs`) the section quotes, whose every non-space character must map through `char_to_symbol` (`components/sections/mod.rs`), the quote split (`utils/quote_split.rs`) and the cluster group counts (`components/sections/experience.rs`, `projects.rs`). Everything that touches the browser is checked by hand or with Playwright against a running `trunk serve`.

### Linting / Formatting

```bash
make lint
make fmt

# Frontend WASM check
cargo check -p portfolio-frontend --target wasm32-unknown-unknown
```

### Build

```bash
# Both
make build

# Or individually:
make build-frontend   # outputs to frontend/dist/
make build-backend
```

`frontend/public/scene.js` and `frontend/public/vendor/` are copied to `dist/` by `copy-file` and `copy-dir` links in `frontend/index.html`. There is no npm step.

## Project-Specific Conventions

1. **Frontend**: Leptos `#[component]` functions, `signal()` / `RwSignal` for state, `Effect::new` for side effects, `view!` macro for markup
2. **Backend**: Async handlers with `Json` response type, CORS enabled via `tower-http`
3. **Styling**: Pure CSS with semantic class names, no Tailwind. `main.css` holds the base, `modern.css` the modern layer (tokens as CSS custom properties, carved-stone surfaces, CSS 3D fallback), `webgl.css` the WebGL mode and the fallback notice. Reuse the tokens (`--ocean-*`, `--stone-*`, `--cyber-*`, `--abyss-*`, `--glyph-*`, `--radius-*`, `--fs-*`, `--status-*`) instead of literals, and keep `DESIGN.md` in sync when you add one
4. **Naming**: snake_case everywhere (all Rust). The one hand-written JS file is `frontend/public/scene.js`
5. **DOM access**: `web_sys` + `wasm_bindgen::Closure` for browser APIs (IntersectionObserver, ResizeObserver, scroll events)
6. **RNG**: `fastrand` crate (enables native `#[test]` without wasm-pack)
7. **Callbacks as props**: `impl Fn(String) + Send + 'static + Clone`
8. **Scroll handlers**: Use `get_untracked()` on signals to avoid reactive tracking overhead
9. **Render mode**: `utils::render::apply()` runs before mount and sets `data-render="webgl"` or `"dom"` (plus `data-render-reason`) on `<html>`. Gate component output with `utils::render::webgl()`, never with your own feature test. WebGL mode needs a hardware accelerated context (`failIfMajorPerformanceCaveat`), so software rendering counts as unsupported
10. **WebGL layer**: `scene.js` loads only in WebGL mode (the module waits for `data-render`), uses the import map in `index.html` (`three` maps to `vendor/three.module.min.js`), and draws slabs, the decode glyph grid and the helix on a fixed canvas behind the content. The DOM keeps layout, text and input
11. **One projection**: the camera is orthographic in CSS pixels and the same rotation is written to the DOM block (`rotateX`, `rotateY`, `scale`). Never add CSS `perspective` to a section while the canvas is on (`webgl.css` resets it). Read slab rects from the untransformed `.section-entrance-wrapper`, never from the block itself. `scene.js` caps tilt and entry scale (`MAX_EDGE_SHIFT`, 6px) so a tall slab keeps its edges on the flat page content; without the cap a 2700px slab slid about 55px and showed a ghost frame above the stone
12. **Rust and JS contract**: in WebGL mode the overlay renders no glyph cells and the helix renders no nodes. `scene.js` reads `data-grid`, `data-cols` and `data-origin` on `.poneglyph-grid-full`, the `decoding` class and `--decode-speed` / `--decode-total` on `.poneglyph-overlay`, and `data-helix` / `data-fade` on `.helix-container`. `scene.js` reads the `.slab-cluster` ancestor to share one decode start time, and every cluster slab keeps its own overlay, grid and `data-origin` in its own coordinates. Change both sides together
13. **Frozen behavior**: the infinite-scroll teleport and the overlay logic are tuned; do not change them while restyling. One CSS rule releases clicks to the content after a decode (`.poneglyph-overlay:has(+ .content-decoded)` in `main.css`); without it the transparent overlay swallows every button and link in the section, so keep it
14. **Accessibility**: honor `prefers-reduced-motion` in CSS and in `scene.js` (no tilt, frozen helix, fade-only decode). On touch, no pointer light or pointer tilt. Keep text at WCAG AA
15. **Section quotes**: `PONEGLYPH_QUOTE` and `QUOTE_AUTHOR` in each section are `pub(super)` and use letters, digits and spaces only (no punctuation, apostrophes or accents).

## Verifying Visual Changes

Never start `trunk serve` or `make dev-frontend` from an agent; the user runs it. Then check with Playwright MCP against the running server:

- Capture at 1440x900, 820x1180 and 390x844. Open each file once to confirm it shows what its name claims.
- The overlay decode gate needs a click (or Enter). Dispatch `new MouseEvent('click', { bubbles: true, clientX, clientY })` on `.poneglyph-overlay` because Leptos delegates `click`.
- `scene.js` is served without a content hash, so after editing it run `await fetch('/scene.js', { cache: 'reload' })` and reload before judging the result.
- With `?debug`, `window.__webgl` reports `version`, `slabs`, `helices`, `mode`, `info()`, `framesStats` and helpers such as `slabScreenRect(i)` and `delayOf(i, col, row)`.
- Run the detector on `frontend/style`, `frontend/index.html` and `frontend/src` (add `{ "detector": { "extensions": [{ "ext": ".rs", "engine": "text" }] } }` to `.impeccable/config.json` first).

```text
│       │   ├── slab_cluster.rs       # 3-slab cluster with one shared decode (Historical Records, Log Pose)

│       ├── hooks/

│       └── utils/
│           ├── poneglyph_converter.rs  # char_to_symbol, text_to_symbols, grid generation

│           └── render.rs               # WebGL vs DOM decision (pure fn + tests)

```

**Key patterns**:

- Cargo workspace with two members: `backend` and `frontend`
- `Makefile` coordinates dev/build/test/lint commands
- Trunk serves frontend with proxy to backend API (`/api/` -> `localhost:3000/api/`)
- Custom scroll behavior with infinite loop illusion (scroll teleportation between transition sections)
- Two renderers behind one DOM: WebGL canvas (default, hardware WebGL required) or the CSS and DOM look (fallback, `?webgl=off`)
- Rust decides the renderer once at startup; JS and CSS follow the `data-render` attribute
- `Closure::forget()` for long-lived JS callbacks (acceptable in SPA context)
- `get_untracked()` on signals in scroll handlers to avoid reactive tracking overhead
- Release profile: `opt-level = "z"`, LTO enabled, single codegen unit for minimal WASM size (~212K). Three.js (692KB) loads only in WebGL mode
